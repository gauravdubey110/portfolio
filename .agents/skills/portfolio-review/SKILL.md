# Portfolio Review Skill

Use after meaningful implementation milestones and especially before final delivery.

Recruiter test:
Can the visitor understand within roughly 10 seconds who Gaurav is, his role, engineering focus, impact, and primary CTA?

Engineering manager test:
Is distributed-systems experience, backend depth, scalability, reliability, performance, full-stack capability, and measurable impact obvious?

Senior engineer test:
Is there technical specificity, credible architecture storytelling, meaningful trade-offs, and a clear distinction between professional work and personal projects? Are confidential details excluded?

Designer test:
Check typography, spacing, alignment, card consistency, color discipline, section transitions, responsiveness, and whether the site feels custom-built rather than templated.

Motion test:
Check purpose, timing, consistency, reduced-motion behavior, mobile simplification, and whether any animation should be removed.

Accessibility test:
Check keyboard navigation, focus visibility, semantic structure, contrast, accessible labels, reduced motion, and touch target sizes.

Mobile test:
Explicitly inspect 360px, 390px, and 768px. Verify no horizontal overflow, readable hero, clean metrics, understandable architecture visual, and touch-friendly controls.

Performance test:
Check runtime errors, network requests, large assets, unnecessary packages, animation cost, initial rendering, and build warnings.

Content test:
Never invent metrics, titles, dates, technologies, projects, awards, or certifications. Use the resume and approved public sources.

Fix identified issues directly when safe. The portfolio is ready only when the engineering story is clear, strongest metrics are memorable, design is intentional, mobile works, motion is restrained, accessibility basics are solid, and there are no obvious runtime/content problems.
